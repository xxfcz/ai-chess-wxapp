  - `analyze.wxss` `.fen-input`：恢复 `-webkit-user-select:text;user-select:text;cursor:text`（必须可编辑）。
- 注意：关掉选中后，运行日志在预览里不能手动框选复制，但日志有「复制全部」按钮走系统剪贴板，无影响。

## 预览面板「跨会话/重开就重置到初始状态」的机制（用户测试痛点）
- 现象：①新会话右侧没有面板，必须重新投递 `.genie`；②切到旧会话能看到面板，但每次（重新）打开都回到「刚进小程序」的状态（FEN/棋盘/导航全无）。
- 机制 ①：右侧结果区只展示**当前会话**投递的产物；`.genie` 是旧会话消息历史里的一条，新会话没有 → 面板不出现。属按设计，非 bug。
- 机制 ②：预览是**每次打开都从代码重建的模拟器实例**，不保留小程序运行时内存态（AppData/globalData/页面栈/已输 FEN/棋盘位置）。
  官方/社区文档也明确 WorkBuddy 预览「刷新就没了」，状态存活依赖 mini-program 自身 `wx.setStorageSync`——且预览模拟器重载时 storage 也可能被清。
  **结论**：WorkBuddy 预览适合「快速看样式/结构」，不适合「带状态反复测试」。
- 对测试的建议：①同一会话内保持面板常开、不要切走再重开（重开=重建=重置）；②改代码后我重投 `.genie` 会重载模拟器=状态清空，先把 UI 探索做完再让我重投；
  ③要带状态反复测（FEN/对弈进度持久），正确路径是「分享→体验版」后在**微信开发者工具/真机**测，那里 localStorage 重开保留；
  ④可给本小程序加 `wx.setStorageSync` 记住上次 FEN（对真机/开发者工具有用，预览模拟器未必保）。
- 用「运行日志」卡片观察引擎输出，不依赖 UI 状态。

## 排障：DevTools 编译报 `module 'pages/analyze/analyze.js' is not defined`
- 现象：WorkBuddy 发布成功，但微信开发者工具编译报 `module 'pages/analyze/analyze.js' is not defined, require args is 'pages/analyze/analyze.js'`，栈在 `injectComponentsRecursively/wrapComponentsInjection`（lazyCodeLoading 注入阶段）。
- 根因：`pages/analyze/analyze.js` 第 976 行 `_focusToken()` 方法以 `}` 收尾但**漏了尾逗号**，下一行 `_proseText() {` 紧跟，JS 对象字面量方法必须逗号分隔 → `SyntaxError: Unexpected identifier '_proseText'`（node --check 定位到 981）。
  模块编译失败所以没注册 → DevTools 报「not defined」。
- 为什么发布成功却编译失败：WorkBuddy「发布」只是打包上传源码 + 生成 `.genie` 清单，**并不跑微信真实编译器**，所以语法错误能过发布；DevTools 才真正编译运行，会抓出语法错误。两者不是同一道校验。
- 修复：第 976 行 `}` 改为 `},`。修复后 `node --check` 对页面+全部 15 个模块全绿。
- 教训：改完页面/引擎后跑 `node --check pages/analyze/analyze.js` 或三套自检，能提前抓这类语法错误，不必等 DevTools 编译。
