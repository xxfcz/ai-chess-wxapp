## 第三轮：采纳导航 + autoCoach/key 追问

- 用户**正式采纳**「Landing 主包 + 各模式分包 page」导航（方案 §1）。
- autoCoach 语义澄清：`on`=任何引擎模式都自动点评；`remoteOnly`=仅云端强引擎模式自动（弱引擎分析偏差大、自动点评低价值且烧 token）；`off`=手动。三档过细则可降为 off/on + UI 文案引导。
- key 为何被提取：小程序 .wxapkg 明文打包、JS 未强加密，反编译即可得硬编码 key 与本地存储；前端密钥不保密。用户自用 key 风险自担，开发者内置 key 必须走服务端代理。已补进方案 §11.4/§11.5。

## 第四轮：autoCoach 三档定稿 + 对弈子策略 + 加密存储结论

- autoCoach **保持三档**（off/on/remoteOnly 已拍板），方案 §11.4 新增「设置页文案」用一行小字向用户解释 remoteOnly 动机（本地弱引擎分析不准、自动点评低价值又费额度）。
- 对弈模式新增子策略 `playCoachScope`（`allSteps` 每步 / `keySteps` 仅关键步）：关键步判定 = 引擎评估波动 |Δcp|≥阈值(默认 80cp，可调) 或吃子/将军等显著变化着法；避免每步自动点评的 token 重与刷屏。§2.3 对弈行「点评触发」列改为读 autoCoach + playCoachScope。
- 加密存储追问结论：本地加密存储**不会本质更安全**——前端要用的 key 终须解密，解密密钥/逻辑同打包在 .wxapkg，逆向即可得，只是混淆非保密；真正保护只有「密钥不进客户端（走自有代理）」。已补进 §11.5。
