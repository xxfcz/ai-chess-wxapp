## 修复：Landing 入口点击报「未找到页面」（预览运行时导航）

**现象**：内置预览面板里点 Landig 任何一个入口都报 `navigationTo: fail 未找到页面`。

**定性过程**：先核对 `app.json` 页面路径 / 磁盘 12 个页面文件 / `navigateTo` 目标三者完全一致 → 不是路径写错。再问出关键信息：**连主包 `pages/placeholder`（学习卡、设置入口）也失败** → 不是分包问题、也不是 `subpackages` 字段大小写问题，而是预览运行时对 **带 query 的 url** 解析与微信原生不同（把整串 url 当页面 key 或只认某种形式）。

**改动**：
- 新增 `utils/navigation.js`：`navigate(url,{host,onFail})` 按候选形式依次尝试（原样 → 去 query → 相对路径 → 相对去 query → redirectTo → reLaunch），任一成功即停；全失败回调 `onFail` 显形；环境不回调任何东西时只上报一次（`NO_CALLBACK_MS=1500`），不盲试下一个 url（避免已跳走还重复跳）。
- `session-store` 新增 `_pendingParams` / `setPendingParams` / `takePendingParams`：走「去 query」形式时把 query 解析结果存起来，目标页 `onLoad` 用 `navigation.mergeLaunchOptions(options)` 取回（一次性、显式 options 优先）。改动落点：`pkg-analyze/analyze`、`pkg-play/play`、`pkg-replay/replay`、`pages/placeholder` 各 onLoad 首行 + require。
- `pages/landing`：四个入口 + 剪贴板导入统一走 `_go()`；新增 `navError` 显形卡片（含「复制详情」），不再静默。
