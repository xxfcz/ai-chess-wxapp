## 诊断：H5 预览「path not allowed」+ 真机 403 的根因与修复

用户报两处报错：H5 预览「[引擎]云端不可用（NETWORK * request:fail path not allowed」、
真机「HTTP 403 · BAD_RESPONSE · 云端引擎返回内容异常」。

**根因（curl 复现确认）**：`ai-chess-server.app.workbuddy.host` 是 CloudStudio 开发预览域名，前面是
`CloudStudio Gateway`。服务端本身不鉴权（curl 直连 200 正常分析）。网关两层拦截：
1. H5 预览：`wx.request` 只允许 `/.cloud/` 路径 → `path not allowed`；
2. 真机：识别完整 iPhone `MicroMessenger` UA → 403 + HTML「请在浏览器中打开」
   （裸 `microMessenger/8.0` → 200，完整 UA → 403）。
即「用 CloudStudio 预览域名当小程序后端，预览与真机都跑不通」；之前"实测 1s"是在微信开发者工具
（桌面 Chrome UA）测的，不代表真机/预览。这是平台限制，非代码 bug，也非服务端故障。

**代码侧修复**（`utils/remote-engine.js` + `utils/ai-client.js`）：新增 `GATEWAY_BLOCK` 环境级屏蔽判定——
`path not allowed` / HTTP 403 / HTML「请在浏览器中打开」均归为此类；命中后本会话标记为 `permanentlyBlocked`，
不再发请求、不再刷屏，回落本地并给出明确中文提示（开发预览域名在微信内不允许直连，正式版需自有已备案域名）。
`describeEngineSource` 为 `GATEWAY_BLOCK` 单独写提示文案（不再是吓人的"返回内容异常"）。
`configure({endpoint})` 换域名会清掉屏蔽标记。

**回归**：`remote-engine.test.js` 新增 §4.3（path not allowed + 403 HTML 两例，断言 GATEWAY_BLOCK /
永久屏蔽 / 之后不再发请求），70 → 76 项；`analyze-page.test.js` 仍 200 项全绿。

**部署侧结论（不在代码内解决）**：要让 `engine: remote` 真机可用，必须把引擎部署到自有 ICP 已备案域名
（路线 C），并配 request 合法域名。已写入 MEMORY.md「云端引擎」节与「待办」。

## 核实：微信云托管容器默认公网出口

`docs/微信云托管反代部署手册.md` 原把「容器出网」列为待核实项（前置确认 + 坑位清单两处）。
现据腾讯云 CloudBase 官方《公网出访》文档核实：**云托管服务实例公网出向流量默认通过平台默认出口访问公网**
（新建服务默认即能出网），故 B1 反代方案的「容器出网」前提**默认成立，无需额外配 NAT**。
两点例外/限制：① 少数 `stand_alone_cluster` 独立集群环境控制台无「公网访问」开关、API `PublicNetStatus`
写不生效，需走 VPC+NAT；② 出口 IP 动态不固定（官方 FAQ Q25 确认非固定），但本项目上游（chess-api.com
与自有香港机）均不要求白名单，不构成阻塞。已把手册两处「待核实」改为「已核实 ✅」并补来源与例外说明。
