## 引擎端点改成外部配置（同日下午）

用户部署了 `https://chess.imex.de5.net/`（香港机，进程池 8，Stockfish 15.1；端到端 400~900ms），
要求端点不再写死在代码里。

- 关键约束：**小程序运行时读不到 `process.env`，也读不到 `.env`**（包内无文件系统/node 环境）。
  所以做成两层：
  1. **编译前注入**：`.env` → `npm run config:engine`（`scripts/gen-engine-config.js`，零依赖自解析）
     → 生成 `utils/engine-config.build.js`。**生成文件必须提交**（require 不到就是编译错误），
     `.env` 进 .gitignore；系统环境变量同名变量优先于 `.env`（CI 可覆盖）。
  2. **运行时覆盖**：代码 `setEndpoint()` > 本地缓存 `wx.getStorageSync('ai-chess.engineEndpoint')`
     > 构建注入 > 内置默认 `BUILT_IN_ENDPOINT`。
- `utils/engine-config.js` 负责解析；`remote-engine.js` 的 `DEFAULT_ENDPOINT` 改由它算，
  `reset()` 会重新解析，日志首行打印「[引擎] 端点 …（来源：env/storage/override/default）」。
- develop 分流：`envVersion === 'develop'` 时优先用 `.env` 的 `ENGINE_ENDPOINT_DEV`
  （可以是 http+IP+端口），release/trial 一律走正式 https 地址——避免调试地址混进正式版。
- `.env` 四个键：`ENGINE_ENDPOINT` / `ENGINE_ENDPOINT_DEV` / `ENGINE_MODE` / `ENGINE_TIMEOUT_MS`；
  地址经 `normalizeEndpoint()` 规整（非 http(s)/空值当没配，回落到下一级，不硬失败）。
- 新增 `.workbuddy/tests/engine-config.test.js`（30 项）。门禁 30+82+153+200+68+48 = **581 项全绿**。
- 文档：`AGENTS.md` 新增 §4.2（配置表 + 换地址流程）、§10 改地址条目、§9 测试清单。
