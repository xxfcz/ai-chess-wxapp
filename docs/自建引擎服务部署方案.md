# 自建引擎服务部署方案（用户已有服务器 · 香港）

> 制定日期：2026-10-13 · 状态：**方案待评审** · 前置文档：`远端引擎接入方案-chess-api.md`
>
> 触发条件：用户提供一台公网服务器 `112.121.168.204`（Debian 12，16C/24G，现跑 mongodb + graylog，
> CPU 2~5%）用于承载 `engine: remote`。本文回答三个问题：**这台机器该怎么用、域名备案怎么走、先做什么**。

---

## 0. 结论摘要

1. **硬件绰绰有余，但服务器在中国香港**——这意味着**不能在该机器上做 ICP 备案**，
   而大陆主体小程序的合法域名必须有备案号。域名与备案成为关键路径（7~20 个工作日），需立即启动。
2. **不建议把香港机器当 chess-api.com 的反向代理，建议直接跑本地 Stockfish**：
   16 核空闲、深度/思考时间/MultiPV 全开放、无公共队列、无第三方依赖。
   chess-api.com 退为期一联调工具与可选兜底上游。客户端契约不变，只改 baseURL。
3. **⚠️ 先处理安全事故再谈部署**：实测 9000 端口确认是 **Graylog Web UI 公网暴露**，
   27017/12201/8080 同样可连通——MongoDB 暴露在公网是勒索软件的头号目标。今天就把防火墙收口。
4. **两条 ingress 路线**：A 域名+备案后解析到香港（便宜、普遍做法、但有接入地不一致的灰色风险）；
   B 微信云托管反代（免域名免备案、完全合规、约 22 元/月）。推荐 A 主线 + B 备选，联调期走 chess-api.com。

## 1. 服务器现状核实（2026-10-13 实测）

| 项 | 实测结果 |
| --- | --- |
| IP 归属 | `112.121.168.204` → **中国香港** Yau Tsim Mong，AS45753 Netsec Limited |
| 系统 | Debian 12（用户提供） |
| 资源 | AMD EPYC 4584PX 16 核 / 24G 内存；mongodb + graylog 在跑，CPU 2~5% |
| 端口连通性 | 22 / 80 / 443 / 27017 / 9000 / 12201 / 8080 **均可从外网连通** |
| 9000 指纹 | `X-Graylog-Node-ID: fe4f992c-...` → **Graylog Web UI 确认公网暴露** |
| 80 / 443 | 可连通但无 HTTP 响应（有东西监听或厂商侧放行，上机用 `ss -tlnp` 核实后再让 Caddy 接管） |
| 延迟 | 本沙盘探测被本地代理终止，数据不可信；**预期大陆用户→香港 10~40ms**，需真机联调实测 |

### 1.1 ⚠️ 安全加固（最高优先级，先于一切部署）

MongoDB（27017）与 Graylog（9000/12201）暴露公网属高危配置，历史被批量扫描勒索。在服务器上执行：

```bash
# 1) 防火墙收口：只放 22/80/443（建议 22 再限源 IP）
sudo ufw default deny incoming && sudo ufw default allow outgoing
sudo ufw allow 80/tcp && sudo ufw allow 443/tcp
sudo ufw allow from <你的固定IP> to any port 22 proto tcp   # 或至少装 fail2ban
sudo ufw enable

# 2) MongoDB 只听本地
sudo sed -i 's/^  bindIp:.*/  bindIp: 127.0.0.1/' /etc/mongodb.conf
sudo systemctl restart mongod
# 确认已启用鉴权：mongo --eval "db.runCommand({connectionStatus:1})" 看 authUsers

# 3) Graylog 不再对公网开放，远程管理走 SSH 隧道
ssh -L 9000:127.0.0.1:9000 <user>@112.121.168.204   # 浏览器开 http://127.0.0.1:9000
# 若 graylog 要收远端日志：用 Tailscale/WireGuard 组网，或 ufw 限源 IP，别开公网 12201

# 4) 核实监听实况（部署前必查 80/443 被谁占着）
sudo ss -tlnp | grep -E ':(80|443|27017|9000|12201|8080)\b'
```

> 以上命令只是标准动作，执行前请按服务器实际配置（mongodb.conf 路径、sshd 配置）核对。
> 引擎服务上线后，公网只需暴露 80/443（Caddy 自动 TLS）。

## 2. 香港位置的两个直接后果

1. **备案不可能落在该服务器上**：ICP 备案的接入地必须是中国大陆。
2. **大陆主体小程序的 `request` / `socket` 合法域名必须带备案号**（微信后台强制， HTTPS/WSS）。
   所以无论引擎跑在 chess-api.com 还是这台香港机器，**域名这一关都绕不过去**——区别只是
   chess-api.com 的域名在别人手上（确定未备案，正式版不可用），而自己的域名可以备案。

---

## 3. 架构决策：本地 Stockfish，而不是代理 chess-api.com

| | 代理 chess-api.com | **香港机器跑本地 Stockfish（推荐）** |
| --- | --- | --- |
| 思考预算 | 免费层死限 100ms / depth ~12 | 自定：movetime 100~2000ms、depth 到 20+ |
| MultiPV | REST 不给，只有 WS 给 | REST/WS 都给，数量自定 |
| 依赖 | 第三方个人服务，随时可能停 | 只有自己 |
| 排队 | 公共队列，高峰要等 | 进程池 + 队列，16 核当前负载下不会排队 |
| 客户端改动 | — | **零分支**：自建服务协议与 chess-api.com 兼容，只改 baseURL |
| 工作量 | 极小（纯反代） | 中（一个 ~300 行 Node 服务 + Stockfish 二进制） |

**结论**：硬件已经闲置，没有理由把算力外包给免费层。自建服务对外暴露与 chess-api.com
**同构的 REST/WS 协议**（见 §4.3），因此 `utils/remote-engine.js` 一份代码同时支持两个上游，
chess-api.com 保留为期一联调目标与兜底上游（配置开关 `ENGINE_UPSTREAM`）。

## 4. 部署清单

### 4.1 Stockfish（无需编译）

```bash
# 官方 release 的 Linux 二进制（比 apt 里的版本新得多；NNUE 网络已内置）
# https://github.com/official-stockfish/Stockfish/releases → stockfish-ubuntu-x86-64-avx2.zip
sudo install -d /opt/stockfish && cd /opt/stockfish
sudo unzip ~/stockfish-ubuntu-x86-64-avx2.zip && sudo chmod +x stockfish
./stockfish bench 2>&1 | tail -2   # 冒烟测试，顺便看 nps
```

### 4.2 引擎服务（Node，进程池）

- **形态**：单文件 Node 服务，启动时拉起 N 个常驻 Stockfish 子进程（默认 4，可配），
  每个 worker 一条 UCI 会话；请求按 `fen` 分发到空闲 worker。
- **worker 参数**：`setoption name Threads value 1`、`name Hash value 256`（4 worker ≈ 1G，内存无压力）。
- **端点**：
  - `POST /v1` —— REST，chess-api.com 兼容请求体（`fen/depth/maxThinkingTime/variants`），
    返回同构 JSON（`move/san/eval/centipawns/mate/continuationArr/debug/turn/...`）；
  - `WS /v1` —— 同构消息协议（`log` → `info` → 按 multipv 分线的 `move` → `bestmove`），
    **额外附带显式 `multipv` 字段**（客户端优先用它，回退到 debug 正则时即连的是 chess-api.com）；
  - `GET /healthz` —— 探活（供 `capabilities.js` 与监控用）。
- **防护**：同 `fen+depth+multiPV+movetime` 结果 LRU 缓存 10 分钟（cap 2000）；
  单 IP 令牌桶 60 次/分（burst 20）；全局并发 ≤ worker 数，排队超 20 返回 503（客户端回落本地）。
- **运行**：systemd unit（`Restart=always`），Node 22 LTS（Debian 12 apt 里的 Node 18 已 EOL，用 nodesource）。
- 代码属期二实施产物，契约以 §4.3 与 `远端引擎接入方案-chess-api.md` §2 为准。

### 4.3 Caddy（TLS 终结 + 反代）

```caddyfile
api.your-domain.com {
    encode zstd gzip
    reverse_proxy /v1* 127.0.0.1:8787      # 引擎服务；WS upgrade 由 Caddy 自动处理
    reverse_proxy /healthz 127.0.0.1:8787
}
```

Caddy 官方 apt 源安装，域名 A 记录指到本机后**自动签发并续期 Let's Encrypt 证书**，零运维。

### 4.4 防火墙与端口

公网只暴露 **80/443**（Caddy）；引擎服务只听 `127.0.0.1:8787`。
§1.1 的收口动作覆盖其余全部端口。

## 5. 域名与备案路线图（关键路径，立即启动）

| 时间 | 动作 | 说明 |
| --- | --- | --- |
| Day 0 | **买域名** | `.com` 约 65~75 元/年（腾讯云/阿里云 DNS 均可）；顺手开 DNSPod 解析 |
| Day 0~1 | 备备案材料 | 个人主体：身份证 + 人脸识别；企业主体：营业执照。网站名称取「棋类分析服务」类，备注写清是国际象棋引擎 API |
| Day 0~1 | 取**备案服务号** | 需一台大陆云服务器（轻量应用服务器新客约 38~99 元/年；已有任何大陆云资源可直接申请）。若完全不想买 → 走 §6 路线 B |
| Day 1~3 | 接入商初审 + 提交通管局 | 初审 1~2 个工作日，之后通管局审核 **7~20 个工作日** |
| 备案期间 | 域名**不解析到香港** | 指向备案用的大陆服务器或不解析，避免"未备案接入"争议 |
| 通过后 | A 记录 → `112.121.168.204` | Caddy 自动签证书；mp 后台配 `request: https://api.域名` + `socket: wss://api.域名` |

**灰色风险（必须知情）**：备案通过后把域名解析到香港，属"备案接入地与实际接入地不一致"。
通管局抽查纠正的概率低但存在，一旦被注销备案，小程序请求全部失败、需重新备案。
完全合规的两个替代：§6 路线 B（云托管反代）或买大陆轻量服务器把引擎也搬过去
（首年 38~99 元、续费约 100~300 元/年，以官网为准；2 核跑 Stockfish MultiPV 仍有余量）。

## 6. Ingress 路线对比（域名关怎么过）

| | A 域名+备案→直连香港 | B 微信云托管反代 | C 引擎迁大陆轻量 |
| --- | --- | --- | --- |
| 正式版可用 | ✓（备案后） | ✓ | ✓ |
| 合规性 | 灰色（接入地不一致） | **完全合规，免域名免备案** | **完全合规** |
| 成本 | 域名 ~70 元/年（+可能买备案用大陆机 38~99 元首年） | ≈22 元/月（0.25 核常驻） | 域名 70 + 大陆机 100~300 元/年 |
| 延迟 | 最低（直连） | +一跳（云托管→香港约 20~40ms） | 最低（大陆内网） |
| 工作量 | 备案等待 + Caddy | 云托管容器 + 一个反代配置 | 同 A 的部署 + 迁移 |
| 冷启动 | 无 | 最小副本 0 时 20~40s，建议留 1 副本 | 无 |

**建议**：A 为主线（今天买域名递备案，时钟先走起来）；若备案受阻或不愿承担灰色风险，
切 B——两种路线下客户端与引擎服务都不动，只改 `remote-engine.js` 的 baseURL。

## 7. 与 chess-api.com 方案的分工

| 阶段 | 上游 | 前置条件 | 状态 |
| --- | --- | --- | --- |
| 期一 · 联调 | chess-api.com 直连 | 开发者工具「不校验合法域名」 | 可立即开始（契约见原方案 §2） |
| 期二 · 自建 | 香港 Stockfish 服务 | 域名备案通过（路线 A）或云托管就绪（路线 B） | 备案是长杠杆，Day 0 启动 |
| 兜底 | chess-api.com（配置开关） | 无 | 自建服务异常时可选切回，也可不配 |

> 注意：自建上线后 chess-api.com 的价值从"主上游"降为"兜底上游"；若不愿保留第三方依赖，不配即可。

## 8. 验收口径

**安全（上线前必须全过）**：
1. 外网端口扫描只见 22/80/443；`ss -tlnp` 确认 mongod 只听 127.0.0.1；
2. Graylog 走 SSH 隧道可访问，公网直连 9000/12201 拒绝；

**引擎服务**：
3. 外网 `curl -X POST https://api.域名/v1 -d '{"fen":"<起始局面>","depth":14,"maxThinkingTime":200}'`
   返回合法最佳着法，`debug` 行含 `multipv 1 score cp ...`；
4. WS 连 `wss://api.域名/v1` 发 `variants:3`，收到按 multipv 1/2/3 分线的 `move` 消息与收尾 `bestmove`；
5. 杀棋局面返回 `mate`（白方视角字符串），与 chess-api.com 符号一致；
6. 限流生效：突发 100 请求不打死服务，超出返回 503 且客户端回落本地引擎；
7. `GET /healthz` 通；systemd 重启后服务自恢复；

**小程序**：
8. 体验版（不校验合法域名）跑通三线分析，记录大陆→香港真实延迟；
9. 备案通过配好合法域名后，正式版链路复测 §8.3~8.4。
