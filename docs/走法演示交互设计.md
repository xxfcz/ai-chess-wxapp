# 棋局走步「交互式点击演示」功能设计与方案

> 本文档记录「AI 教练点评 → 走法演示」功能的背景、设计原则、协议、交互细节与质量保障。
> 配套代码：`utils/coach-demo.js`（纯逻辑）、`utils/game.js`（`applySan`/`pieceSquares`）、
> `utils/board-model.js`（焦点高亮）、`utils/ai-client.js`（提示词 + 输出长度）、`pages/analyze/*`（集成）。
> 测试：`utils/...` 纯 Node 自测 + `.workbuddy/tests/{engine-and-game,analyze-page,coach-demo}.test.js`。

---

## 1. 背景与目标

原版小程序能生成一段中文 AI 点评（纯文本），但用户无法直观理解「点评里提到的走法到底怎么走」。
本功能把点评文本里的**走法、格子、棋子**自动变成可点击链接，点击后：

- 在棋盘上**按点评思路逐步重放**对应走法；
- 支持**多分支**：分支可能从「被点评局面」起，也可能从「某条线走几步后的局面」继续；
- 让用户**始终清楚当前身处哪条线、第几手、继承自哪条线**；
- 演示跑在**临时副本**上，不污染用户真实棋局、不触发自动分析，一键退出。

经过多轮迭代，最终形态还包含：分支走法**独立列表且完整列出全部步骤**、位置/棋子**独立配色高亮**、富文本与分支**均可复制**。

---

## 2. 核心设计原则：解耦

用户明确要求「与原有功能尽量解耦」。最终落地为：

- **所有演示逻辑收进一个纯模块 `utils/coach-demo.js`**（无 `wx` / 无 DOM / 不 import 页面），
  只依赖 `utils/game`（纯状态层）与 `utils/board-model`（共享视图层）。
- **页面只做薄薄的「事件转发 + 演示期只读守卫」**：通过 `DemoSession.view()` 取渲染数据，通过几个事件方法驱动演示。
- **既有引擎 / 走子 / 云端点评逻辑零改动**：
  - `utils/game.js` 只新增一个纯增量方法 `applySan(san)`（不修改其它方法行为）；
  - `utils/board-model.js` 只新增 `focus` 高亮参数；
  - `utils/ai-client.js` 只在提示词末尾追加演示线规范、并把 `MAX_TOKENS` 上调留出余量。

这样演示功能即使出问题，也不会拖垮核心对弈与引擎分析。

## 3. 结构化协议（`===DEMO===` 块）

演示数据由大模型在点评正文之后**按约定格式追加**一段 JSON，解析端用定界符抽取，
且抽取后**整块剔除**，保证 UI 不会露出原始 JSON。

```
===DEMO===
{"lines":[
  {"id":"main","label":"主线走法（Kg2）","tone":"good",
   "desc":"最推荐的顽强防守。后续黑方若走 Qxd5，虽有 Bxh3+，但白王可安全逃到 g3。",
   "base":"root","moves":["Kg2","Qxd5","Kg3"]},
  {"id":"avoid","label":"对比走法（Ke2）","tone":"bad",
   "desc":"错误的劣着。黑方会接 Qc4+ 再 Rxf3，白方白白多丢一个马。",
   "base":"root","moves":["Ke2","Qc4+","Rxf3"]}
]}
===END===
```

字段约定：

| 字段 | 含义 | 约束 |
|------|------|------|
| `id` | 线的唯一标识 | 字符串；其它线用 `base.line` 引用它 |
| `label` | 线上展示的标签（如「主线走法（Kg2）」） | 中文短标签 |
| `tone` | `good` / `bad` / `neutral` | 决定排序（good 最前）与配色基调 |
| `desc` | 一句话点评该线（≤40 字，超出截断 80 字） | 文案里可直接写 SAN/格子/棋子，系统自动变链接 |
| `base` | 起点锚点 | `"root"`（或被省略）= 被点评局面；`{"line":"<id>","ply":<第几手,1 起>}` = 从某线第 N 手后继续 |
| `moves` | 本线着法序列（标准 SAN） | 最多 8 手（实际提示词要求 ≤6）；逐手校验 |

> **提示词约束关键点**（`utils/ai-client.js#COACH_SYSTEM_PROMPT`）：
> - 最推荐的走法**必须**作为 `tone=good` 的线输出（不能只写进正文）；
> - `moves` 必须从该线起点起逐手合法且黑白交替，注意别被己/对方子挡住、别吃不存在的子、将军才加 `+`；
>   不确定的着法**宁可不写**；
> - 王车易位写 `O-O` / `O-O-O`，不要写 `0-0`；
> - 没有合适演示线时，直接不输出 `===DEMO===` 段。

### 解析容错（关键健壮性设计）

模型偶尔会写出「实际走不到」的着法（如被己方/对方子挡住）。解析端做两层保险：

1. **截断保留**（`resolveMoves`）：某手非法时，保留前面合法的若干手作为该线展示与重放内容，
   不再「整条丢弃」——否则推荐线会整个消失、正文里的走法也失去链接。
   只有「第一手就非法 / base 引用非法 / 成环」才丢弃整条。截断会以 `console.warn` 暴露，
   可在「运行日志」卡片看到是哪一手被拦。
2. **SAN 规范化**（`normalizeSan`）：挽救常见非标准写法——去掉误加的回合号前缀（`1.Kg2`→`Kg2`）、
   去掉尾部评注符（`Qc4+!?`→`Qc4+`）、易位零写法（`0-0`→`O-O`）；展示用引擎回吐的规范 SAN，与重放一致。

`base` 锚点链支持「线套线」递归，带**成环检测**（`visited` 集合），环与非法祖先都会丢弃该线。

## 4. 交互功能点

### 4.1 走法可点 + 逐步演示

- `tokenizeText(prose, {lines,colorMode:'branch'})` 把点评正文切成片段：
  只把**确实命中某条演示线 `moves`** 的 SAN 记号标成可点（长度优先 + 上下文线优先匹配），其余正文照常显示。
- 点击走法 → 页面 `onCoachTokenTap` → `DemoSession.enterAt(line, ply)` 把该分支演示到对应手数。
- 演示区提供 **上一步 / 下一步 / 播放（350ms/手）/ 退出演示** 控制；播放用 `setInterval` 驱动，
  播放结束或用户手动操作即停止。

### 4.2 临时副本 + 面包屑（始终知道「我在哪」）

- `DemoSession` 构造时 `new Game(rootFen)`（rootFen = 被点评局面），演示完全跑在这份副本上；
  切换线 / 走步都 `_rebuild()` 从 root 重放，绝不修改页面真实棋局、不触发自动分析。
- `view().breadcrumb` 输出形如：
  `演示线：白方续攻 · 第 2/3 步 · Nc6（自「避免：冲 d4」第 2 步后起）`
  —— 明确告知：线标签 / 第几步 / 当前手 / 继承自哪条线第几手。
- 演示期棋盘**只读**：`pressSquare`、`onCellTap`、`onCellTouch*`、`onUndo/Redo/Reset/LoadFen`
  等以 `this.demoActive()` 提前 `return`，防止用户在演示时误改真实棋局。
- 退出演示（`onDemoExit`）销毁临时副本、`syncAll()` 让棋盘回到真实棋局。
- 退出后再次点击点评/分支里的记号，会经 `_ensureDemo()` **重建演示会话**，无需重新生成点评。

### 4.3 分支走法独立列表（含完整步骤 + 双着色）

- 每条分支（含主线）独立成块：`lineViews()` 输出 `{ label, tone, cls, segs, moves }`。
  - `label` 按线序号配色（`demo-label-0/1/2` → 蓝 / 橙 / 紫），一眼对应正文链接颜色；
  - `segs` = 该线 `desc` 的片段（见 4.4 配色）；
  - **`moves` = 该线完整走法序列**，由 `buildMoveSegs()` 切成可点片段，带回合号（标准记谱：白步标 `N.`、黑步跟随），
    每个走法点一下即 `enterAt` 跳到那一手。`base` 前缀只作已下完的起始语境，**不重复列出**。
- 着色分两套、互不混淆：
  - **点评正文**里的链接按**分支**着色（`ln-0` 蓝 / `ln-1` 橙 / `ln-2` 紫）；
  - **分支列表**（描述与走法序列）里的链接按**行棋方**着色
    （白方手 `side-w` 亮白 / 黑方手 `side-b` 浅灰，贴合棋子配色）。
    行棋方由 `moverOf()` 依据 `resolved` 序号奇偶 + root 行棋方推算，**模型无需标注黑白**。

### 4.4 位置 / 棋子链接 + 紫色焦点高亮

`tokenizeText` 在正文与 `desc` 里识别三类记号：

1. **走法（move）**：SAN 命中演示线 → 点击演示到对应手。
2. **棋子（piece）**：`黑/白 + 后车象马王兵`（如「黑后」「f3马」）→ token 形如 `bq`；点击经 `findPieces()`
   在当前演示局面上动态查找该子的实际格子（可多格），并高亮。
3. **格子（sq）**：`[a-h][1-8]`（如 e5、h2、d6）→ 点击把对应分支上盘后高亮该格。

边界校验保证不误切：`Kg2`/`Rad1` 这类 SAN 内部的格子被边界规则挡住不拆；而「c1象」里的 `c1`
作为合法格子可点（「象」保持正文）。格子若是某分支某一手的落点 → 演示到那一手再高亮；否则停在起点高亮。

**高亮配色独立**：新增 `.cell.focus`（紫色内阴影 + 内描边，`rgba(176,92,255,.55)`），
与 `lastMove`（琥珀）/ `hint`（蓝）/ `sel`（琥珀）/ `check`（红）明显区分；换线 / 走子 / 退出自动清除。
无演示语境时，点击直接在**真实棋盘**上高亮（任何真实棋盘交互即清除）。

> 一个实现细节修正：可点记号在 WXML 里统一带 `seg-move` 再叠加修饰类（`ln-1` / `side-w` 等），
> WXSS 把这些修饰色改为**独立规则**（不再要求 `.seg-move` 同场），否则当初实测分支/黑白配色并未真正上色。

### 4.5 复制能力（富文本 + 分支均可复制）

- 纯文本导出函数（无 wx/DOM）：`movesPlainText`（棋谱式带回合号）、`linePlainText`（「• 标签（N手）：desc\n  走法：…」）、
  `branchPlainText`、`coachPlainText`（正文 + 分支）。
- `utils/device.js` 新增安全封装 `copyText()`（成功 toast「已复制到剪贴板」，失败降级提示）与
  `actionSheet()`（无此接口返回 `false` 让调用方降级直接复制）。
- 页面入口：点评卡头「复制」按钮（无需长按即可用，照顾预览环境）+ 长按整段点评 / 长按某条分支。
  `onCopyCoach` / `onCoachLongPress` / `onLineLongPress` 共用 `_openCopyMenu(lineId)`：
  按可用内容组装菜单（这条分支 / 全部分支 / 点评原文 / 全部），只有一项时直接复制，多项才弹微信操作菜单。

### 4.6 纯文本点评区已移除

点评完成一律渲染为富文本片段（走法/格子/棋子可点），不再有纯文本兜底；
流式生成期间就实时 `stripDemoBlock`，原始 JSON 不会闪现。

## 5. 配色方案总览

| 要素 | 配色 / 类 | 说明 |
|------|-----------|------|
| 走法落点 lastMove | 琥珀 inset 阴影 | 复用既有 `.cell.last` |
| 提示 hint | 蓝 inset 阴影 | 复用既有 `.cell.hint` |
| 被将军 check | 红 inset 阴影 | 复用既有 `.cell.check` |
| **位置焦点 focus** | **紫 `rgba(176,92,255,.55)` + 内描边** | 新增 `.cell.focus`，与上面三者区分 |
| 正文链接（分支） | `ln-0` 蓝 / `ln-1` 橙 / `ln-2` 紫 | 按线序号 |
| 分支列表（行棋方） | `side-w` 亮白 / `side-b` 浅灰 | 按该手行棋方 |
| 分支标签 chip | `demo-label-0/1/2` 同色系 | 与正文链接对应 |
| 可点记号 | `.seg-move` + 修饰类 | 统一带 `seg-move` 才正确上色 |

## 6. 预览环境约束与遵守

网页版预览只实现微信接口子集，演示相关改动严格遵守既有模板硬约束
（`analyze-page.test.js` §13 静态守卫）：

- `wx:for` 元素**自身属性**不引用循环变量 `index`，只用 `item.*`；
- `wx:key` 用**字符串字段**（`key: 'seg'+i` 等）；
- 不使用 `<block>`，用独立 `wx:if` / `wx:elif`；
- 可点记号 `item.move` / `seg` 为空时**不解引用属性**，避免预览空指针；
- 依赖 `wx` 的能力（如 `actionSheet`）一律经 `device.js` 探测降级，不因「复制/菜单」本身抛错。

## 9. 已知限制 / 注意事项

- `desc` 由模型生成；若模型偶发漏写某线 `desc`，该分支仍会照常列出**完整走法序列**（来自 `moves`，不依赖 `desc`），描述行为空——不影响「完整步骤」要求。
- 截断保留意味着偶尔推荐线比模型打算给的少几手（有意降级：部分正确好过整条消失）。
- `bindlongpress` 在真机/开发者工具正常，网页预览对其映射不保证，故保留了「复制」按钮兜底。
- 预览模拟器每次重开都重建实例、不保留状态；带状态反复测试请用「分享 → 体验版」走微信开发者工具/真机。
