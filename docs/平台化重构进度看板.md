## 2. 下一步 · L2 Landing 首页 + 多模式分包

### 2.0 前置约束（必读，来自方案 §1 / §7 / memory）
1. **分包结构**：`app.json` 用 `subpackages` 字段；主包只含 `app` + 共享库（L0 `session/engine-service/analysis-service/coach-service/comment-model` + L1 五个组件）+ Landing 页。各模式是**独立分包 page**，构建去重不重复打包。主包上限 **2MB**，别把共享库塞进每个分包。
2. **全局 store**：把当前 `session` 实例 + 已分析节点缓存进 `app.globalData` 或自写单例，跨 page 保留。远程引擎无状态、本地引擎纯函数，重入 page 只重渲 UI、不重算已分析局面（方案 §1 澄清）。
3. **导航模型**：Landing 卡片 → 配 session 模式 → `wx.navigateTo` 分包 page；返回 Landing / 切模式 → 全局 store 保留 session。
4. **扩展方式**：加模式 = 加一个分包 page + 在 Landing 注册一张卡片（方案 §0）。
5. **WXML 静态守卫继续遵守**：循环变量规范、`wx:key` 必填、禁用 `<block>`；新 page + 其组件要并入 `analyze-page.test.js §11` 的扫描集合（先剔除 `<!-- -->` 注释防误伤）。
6. **不新增底部 tabBar**（≤5 上限，且会与模式内子 Tab 冲突）。
7. **剪贴板探测下沉**：当前 `onShow` 剪贴板逻辑只在 `pages/analyze`，方案 §11.6 要求 Landing 也探测。建议抽成共享 util（如 `utils/clipboard-import.js`），Landing 与 analyze 共用，避免重复（见 L2-T5）。

### 2.3 硬阻塞 / 风险（来自方案 §7 + memory）
- **主包体积**：共享库 + 5 组件 + Landing 必须控制在 2MB 内；分包公共依赖走构建去重。
- **引擎端点真机可用性**：`engine:remote` 真机受 `GATEWAY_BLOCK` 永久屏蔽（`app.workbuddy.host` 预览域名 + 移动 UA 403），需自有 ICP 备案域名 + mp 后台配 request 合法域名（memory 远程引擎段）。代码侧已显形提示，不阻塞分包结构本身。
- **回归守护**：拆/迁页面与新增组件，WXML 静态守卫必须继续满足；建议每条新 page 配独立 `*.test.js`，核心流程纳入门禁。
- **设置页依赖**：`autoCoach`/`playCoachScope`/`llm-provider` 概念已定（方案 §11.4/§11.5），但设置 UI 是否已存在需 T2 时确认；缺失则同会话补 `pages/settings`。
