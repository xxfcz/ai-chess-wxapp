# 发布环境与域名白名单速查（黑白格大师）

> 适用范围：微信原生小程序 `ai-chess-wxapp`。
> 本文聚焦三件事：**AppID 归属 × 宿主 × 版本形态** 下，小程序能连什么、连不上什么、需要满足什么前置条件。
> 不展开业务功能；开发版/体验版/正式版的基础概念见 `docs/开发版与体验版的区别.md`。

## 1. 先分清三组概念（混用会得出错误结论）

### 1.1 AppID 归属 —— 决定能力天花板

|---|---|---|---|---|
| 测试号 | `wxe918…` / tourist | ❌ | ❌ | ❌ |

| WorkBuddy 平台应用 id | `wbapp_a2yIza6bMcvSBfKcMQI3CP` | —（**不是微信 AppID**，只是 WorkBuddy 内部应用标识） | — | — |

### 1.2 宿主

- **微信开发者工具**：模拟器 / 真机调试 / 预览扫码 —— 三者都属「开发版」，用 `project.config.json#appid`。
- **WorkBuddy**：右侧预览面板（**沙箱，与 AppID 无关**）；「分享」发布只是**上传 / 提审通道**，不改变 AppID 归属——绑你的号就用你的号。

### 1.3 版本形态

- 开发版（仅开发者可扫）→ 体验版（体验成员）→ 正式版（所有人）。
- **WorkBuddy 有两种发布方式**：
  - 「**创建试用版小程序**」→ 平台试用号，14 天 / 15 人，**不能转正式版**；
  - 「**绑定已有小程序账号**」→ 发到**你自己的号**（体验版 / 正式版都能发，绑一次即可，体验/正式共用）。
- **体验版 / 正式版强制校验域名，没有关闭开关**；只有开发版可用 `urlCheck:false` 绕过。

**读法（三句话）**

1. **引擎只在「AppID 是你自己的号」时通**：开发者工具 4~8、WorkBuddy 绑定已有账号 10b/11 都 ✅；平台试用号 10a 与预览面板 9 是 ❌。
2. **LLM 在所有已配 `mp-api` 白名单的宿主都通**；平台试用号天然通（`mp-api` 本就在平台白名单内）。
3. **`wx.cloud` 只有自有 AppID 开通云开发后才有**；测试号与平台试用号都没有。

### 2.1 为什么 9 / 10a 的引擎是 ❌（而不是 ⚠️）

- **9 预览面板**：沙箱对 `chess.imex.de5.net` 一律 `path not allowed`，与 AppID / 域名白名单无关，**用户侧无解**。
- **10a 创建试用版小程序**：平台受管号的服务器域名由平台管控，`chess.imex.de5.net` 不在其中 → `not in domain list`，**你无权添加**。
- 两类根因不同（**沙箱路径 vs 域名白名单**），但结论一致：改配置解决不了。
- 对照：**10b/11 绑的是你自己的号**，引擎按你的白名单走 → ✅。这正是「能力看 AppID、不看谁发布」。

### 2.2 关于「自有 AppID 调 WorkBuddy 网关」那一格的边界

- **网络层**：只要 `mp-api.app.workbuddy.host` 已白名单 + 域名已备案，`wx.request` 就能到。
- **鉴权层**：网关按 `x-wb-webapp-access-key: <publishableKey>` 鉴权，**不校验微信 AppID**；当前 key `wbpk_a2yIza6bMcvSBfKcMQI3CP_…` 属受管应用，未被吊销即可用。
- **风险**：这是**外部平台行为**。若 WorkBuddy 后续收紧网关校验（例如强制只认平台号），这一格会退回 ❌ —— 不是本项目能控。要长期稳，自有 AppID 的 LLM 建议走**自己的云函数/自有网关**。

### 2.3 AppID 怎么设：两个配置项 + 一条发布通道（**可以分开，但推荐指向同一个号**）

| 配置位置 | 填什么 | 生效范围 |
|---|---|---|
| `project.config.json#appid` | 微信 AppID（`wx…`） | 开发者工具：本地编译 / 模拟器 / 真机调试 / 预览扫码 / 上传 |
| `.wbapp_*.genie#appId` | WorkBuddy 平台应用 id（`wbapp_*`） | WorkBuddy 预览面板 / 云服务应用标识（**不是微信 AppID**） |
| WorkBuddy「分享 → 绑定已有小程序账号」 | **不填 AppID，管理员扫码授权** | WorkBuddy 发布体验版 / 正式版（发到你的号） |

**四条铁律**

1. 两个配置项**各管各的、互不冲突**，不需要「改」其中一个去迁就另一个。
2. `wbapp_*` **永远不要**写进 `project.config.json`（会触发真机调试 `-50005`）。
3. **同一 AppID 下，体验版只有一个槽位**：开发者工具「上传 → 选为体验版」与 WorkBuddy「绑定后发布体验版」会**互相覆盖**，后传的赢。
4. **两个不同 AppID = 两个独立小程序**：openid 不同、`wx.storage` 隔离、用户/画像/错题本不能跨渠道合并；名称、备案、审核也各自独立。

> **推荐**：两边指向**同一个自有 AppID**（开发者工具填 `wxd3f1…`，WorkBuddy 扫码绑同一个号）。
> 这样 4~8 与 10b/11 全部「引擎 ✅ + LLM ✅」，唯一缺口只剩预览面板沙箱（9）。
> 反例：WorkBuddy 走「创建试用版小程序」→ 拿到的是平台号，引擎必 ❌，且 14 天到期、不能转正式。

### 2.4 为什么预览面板连不上任何外部域名（含 `*.app.workbuddy.host`）

预览面板的 `wx.request` 是**本地 shim**，不是真实网络栈。实测代码在
`resources/extensions/workbuddy-baas-v2/server/index.cjs`：

```js
var parsed = new URL(rawUrl, location.origin)
if (!parsed.pathname.startsWith('/.cloud/')) {
  opts.fail({ errMsg: 'request:fail path not allowed' })
  return
}
var target = parsed.pathname + parsed.search   // 只保留 path + query
fetch(target, { ... })                         // 相对 URL → 打到预览页自己的 origin
```

三条结论：

1. **只校验 pathname，不校验 host** —— 换域名（`chess.imex.de5.net` / `ai-chess-server.app.workbuddy.host`）结果完全一样，都是 `path not allowed`。
2. **host 被丢弃**：`target` 只剩 path + query，`fetch` 是相对请求 → 实际打到**预览页自己的 origin**，不是原始域名。所以哪怕在自己服务器上挂 `/.cloud/v1`，预览面板也**不会**请求到它。
3. 唯一能服务 `/.cloud/*` 的是**平台侧预览代理**（只提供 LLM / 云服务），不提供自定义引擎转发。

→ 预览面板要真引擎只有两条路：**平台开放 `/.cloud/*` 自定义代理**（不可控），或**端上跑 WASM 引擎**（包体 2MB 上限 + 沙箱能力限制，不建议）。当前实践：**预览面板就用本地 `utils/engine.js`**，这是设计内行为，不是故障。

**`ai-chess-server.app.workbuddy.host` 的真实定位**

| 目标 | 桌面 UA（curl / 浏览器） | 移动 MicroMessenger UA | 预览面板 |
|---|---|---|---|
| `https://chess.imex.de5.net` | ✅ 200 | ✅ 200 | ❌ `path not allowed` |
| `https://ai-chess-server.app.workbuddy.host` | ✅ 200（`/healthz` 与 `/v1` 都正常） | ❌ `POST /v1` **403 + HTML「请在浏览器中打开」** | ❌ `path not allowed` |

- 它**只能当浏览器 / CI / curl 的调试后端**，不能用于真机、体验版、正式版；对移动 UA 的网关拦截仍在（2026-10-15 首次发现，2026-10-23 复测仍复现）。
- 预览面板那一路更彻底：**连 host 都不看**，挂 `/.cloud` 别名也没用（见上面第 2 条）。

**界面怎么说的（2026-10-23 起）**

以前所有降级都弹同一句「云端引擎不可用」，在预览面板里会让人以为引擎坏了。现在按根因分三类，代码落在
`utils/remote-engine.js#blockKindOf` + `utils/analysis-service.js#describeEngineSource`：

| 根因码 | 触发 | 界面提示（`engineNotice`） | toast |
|---|---|---|---|
| `PREVIEW_SANDBOX` | `request:fail path not allowed` | 「预览环境只放行平台云服务，访问不到外部引擎，已使用本地引擎……**这不是引擎故障**；真机 / 体验版 / 正式版不受影响。」 | 预览环境用本地引擎（正常现象） |
| `GATEWAY_BLOCK` | 403 + 非 JSON（网关 HTML）/「请在浏览器中打开」 | 「后端地址在这个环境里无法访问……正式版请改用自有已备案域名（https）。」 | 外部引擎不可达，已改用本地引擎 |
| 其余（超时 / 排队 / 限流 / 未联网） | 服务端波动 | 「云端引擎 + 原因，已自动改用本地引擎。」 | 云端引擎不可用，已改用本地引擎 |

> 判定顺序有讲究：`path not allowed` 先认，之后才轮到 403 分类。`state().blockedKind` 会暴露当前根因，
> Landing 调试面板的探测结论也改成「预览沙箱……真机/体验版不受影响」，**看到这句就不用再查引擎了**。

## 3. 要求清单（每类能力的前置条件）

| 能力 | 目标地址 | 域名要求 | 白名单 | 证书 | 备注 |
|---|---|---|---|---|---|
| 云端引擎 | `https://chess.imex.de5.net` | **固定域名 + 已 ICP 备案** | 自有 AppID 需加 request 合法域名 | 有效 HTTPS（现至 2027-01-14） | 裸 IP:端口只能在开发版 `urlCheck:false` 下用，release 不可用 |
| LLM 云服务 | `https://mp-api.app.workbuddy.host` | 平台域名 | 自有 AppID 需加 | 平台证书 | 平台侧（试用号 / 预览面板）天然在白名单 |
| 自有云函数 | `wx.cloud.callFunction` | **无需域名** | **免白名单** | 无需 | 需自有 AppID 开通云开发；出网不受限 |
| 任意第三方 | 自填 `BASE_URL` | 固定域名 + 备案 | 需加白名单 | 有效 HTTPS | 别在前端存 key |
| 裸 IP 调试 | `http://IP:端口` | 无 | 免（`urlCheck:false`） | 无 | **仅**开发者工具 / 真机调试 + 开发版；上线禁 |

要点：

- **「已备案」是小程序服务器域名的硬门槛**：裸 IP 与未备案域名在 release 一定配不进去。
- `urlCheck:false` 只是开发工具的本机开关，**不是安全边界**；release 一律按白名单。
- 域名白名单**只认 HTTPS**，HTTP 明文域名无法加入 request 合法域名列表。
- 域名必须是**固定 DNS**，不能是会漂移的临时解析（否则证书/白名单校验会间歇性失败）。

## 4. 「全通」到底差哪一格

**先修正一个常见误解：发布渠道（开发者工具上传 / WorkBuddy 发布）不决定能力，AppID 才决定。**

- 若 WorkBuddy **绑定你的号**：4~8 与 10b/11 其实是**同一个 AppID、同一套白名单** → 引擎 + LLM 全通，「四环境全通」基本成立。
- 若 WorkBuddy 走**创建试用版**：拿到的是平台号 → 引擎 ❌。这是「两个 AppID」里最差的那半。
- **唯一与 AppID 无关、怎么配都过不去的**：WorkBuddy 右侧**预览面板的沙箱**。它只放行 `mp-api` 的 `/.cloud/*`，`chess.imex.de5.net` 一律 `path not allowed`。

所以结论要分三种问法：

| 目标 | 能否 | 条件 |
|---|---|---|
| 开发者工具 4 形态 + WorkBuddy 体验/正式 全通 | ✅ 能 | WorkBuddy **绑定自有号**（推荐） |
| 连 WorkBuddy 预览面板也通引擎 | ❌ 不能 | 除非平台在 `mp-api` 域下开放自定义代理函数（用户不可控） |
| WorkBuddy 走「创建试用版」还想通引擎 | ❌ 不能 | 平台号白名单加不了；且 14 天后注销 |

> 一句话：不是「没有全通方案」，而是「**全通的唯一缺口是预览面板沙箱**；其余格子只要把 AppID 统一到自有号就会全部满足」。
> 原「云代理」方案的定位不变：解决 **Key 安全** 与 **白名单**，前提仍是自有 AppID。

## 5. Pragmatic 建议（按目标选路线）

1. **日常开发 / 联调** → 用「自有正式 AppID + 开发者工具（模拟器/真机调试）」。`urlCheck:false` 可少配白名单，改完再上传体验版验真实链路。
2. **给别人看 / 内测** → 用「自有正式 AppID 体验版」：**引擎 ✅ + 点评 ✅**（白名单 + 备案 + 有效 key 齐全），加体验成员即可。这是**当前能力最全**的形态。
3. **WorkBuddy 发布** → 先在「分享」里确认是哪种方式：**绑定已有小程序账号** = 发到你自己的号，**引擎 ✅ + 点评 ✅**；「创建试用版小程序」= 平台号，引擎 ❌ 且 14 天到期。要做产品就绑自己的号。
4. **WorkBuddy 预览面板** → 适合看 UI/交互 + LLM 联调；沙箱 shim **丢弃 host、只放行 `/.cloud/*`**，任何外部引擎域名（含 `*.app.workbuddy.host`）都进不来。**不要在这里判断「引擎坏了」**。
5. **发布前 checklist** → mp 后台「服务器域名 → request 合法域名」必须含 `chess.imex.de5.net` **和** `mp-api.app.workbuddy.host`。少加后者 = 引擎正常、点评永远失败，而报错只显示「网络连接失败」。
6. **换 key 后必须重传** → 已发布的包仍是旧 key；只改 `cloud-config.js` 不重新上传，线上不会生效。
7. **Key 安全** → 第三方 LLM / 引擎 Key 绝不进前端包（前端明文可被反编译）。要自建代理就放云端环境变量，并防 SSRF（限 https、禁内网 host）。
8. **先探测再猜** → Landing 调试面板的「开始探测」只读地探 `GET /healthz` + `POST /v1`，按 `path not allowed` / `not in domain list` / 403 / 超时分类。四个宿主失败原因完全不同，别靠猜。
9. **不要用测试号验真实链路** → 它不能配白名单、不能开云开发，很容易得出「引擎/点评坏了」的错误结论。
10. **AppID 统一优先** → 能用一个自有号就用一个：开发者工具填 `wxd3f1…`，WorkBuddy 扫码绑**同一个**号。分开成两个号只在「想拿平台试用版快速体验」时才有意义，代价是引擎断、14 天到期、数据割裂。
11. **长期稳态** → 若后续要摆脱对 WorkBuddy 网关的依赖，再把 LLM 迁到自有云函数（免白名单、Key 在云端、需防 SSRF）。这是可选优化，**不是「全通」的前提**。

## 6. 诊断锚点（报错 → 根因 → 处理）

| 现象 / 报错 | 根因 | 处理 |
|---|---|---|
| `path not allowed` | WorkBuddy 预览面板的沙箱路径白名单 | 换宿主；沙箱内别用引擎。界面现在会明说「预览环境……不是引擎故障」（`PREVIEW_SANDBOX`），**看到这句不用再排查** |
| `not in domain list` | 域名不在当前 AppID 的白名单 | 自有号：后台加；**平台试用号：无解** |
| 真机调试 `-50005 连接断开` | `project.config.json#appid` 被填成 `wbapp_*` | 改回微信 AppID（`wx…`）；`wbapp_*` 只留在 `.genie` |
| 体验版被覆盖 | 同一 AppID 下体验版**只有一个槽位** | 开发者工具与 WorkBuddy 只用一条链路发体验版 |
| `401 invalid_client` | `publishableKey` 被吊销 / 应用被删 | 重新开通云服务换 key，并**重传体验/正式版** |
| `403` + 非 JSON | 网关/风控拦截（非环境屏蔽） | 换 UA / 域名；按普通失败回落 + 熔断 |
| `net::ERR_EMPTY_RESPONSE` | 明文 HTTP + 裸 IP 被中间设备干扰 | 改 HTTPS 域名 |
| 「网络连接失败」 | 常见是 `mp-api` 没加白名单 | 补 `mp-api` 到 request 合法域名 |
| 模拟器通、体验版断 | 忘了体验版强制校验 | 配白名单（不是改代码） |

## 7. 跨版本 / 跨环境的共享与污染

- 同一 AppID + 同一微信用户：**`wx.storage` 共享**（开发版 / 体验版 / 正式版互通）。开发版改的设置，体验版打开时还在。
- 云服务是**同一套环境**：开发期写入的测试数据会直接落进正式数据。
- 建议：写入端打**环境字段**（如 `env: develop | trial | release`），后续做跨模式画像 / 错题本时按环境过滤。
