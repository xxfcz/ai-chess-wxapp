> **读者**：要改 `E:\projects\ai-chess-wx` 的 AI 助手。
> **本文是「服务端 ↔ 小程序」的对接手册**，字段语义均以 2026-10-14 对线上服务实测为准。

---

## 0. 三句话结论

1. **协议与 chess-api.com 同构**，客户端判错一律看 `body.type === 'error'`，不改判错逻辑就能在两个上游间切换。
2. **REST 就能拿 MultiPV 三线**（自建增强，chess-api.com 的 REST 不给），所以小程序**可以完全不走 WebSocket**——这规避了「socket 全局仅 1 个」「预览环境没有 `connectSocket`」「要配两个合法域名」三件事。
3. **分数有两套视角**：顶层 `eval`/`centipawns`/`mate` 是**白方视角**（兼容 chess-api），`lines[].scoreCp`/`scoreMate` 是**行棋方视角**（与端上 `engine.js` 契约一致）。**小程序请只用 `lines[]` 那套**，别自己换算。

### 1.1 契约是「可发现」的

服务自带三份自述，不需要先知道文档在哪：

| 入口 | 内容 |
|---|---|
| `GET /` | 服务自述：端点清单、分数视角约定、判错方式、引擎版本 |
| `GET /docs/json` | **OpenAPI 3.1 spec**（机器可读，可直接生成客户端代码） |
| `GET /docs` | Swagger UI，浏览器打开即可发请求试 |

> spec 由路由上的 JSON schema 生成（`@fastify/swagger`），与请求校验**用的是同一份 schema**——
> 因此不会出现「实现改了、文档没改」。本文的字段表与 spec 一致；有出入时**以 spec 为准**。
>
> 生产可用 `DOCS_ENABLED=false` 关掉后两个入口（`GET /` 始终保留）。

## 3. `POST /v1` 请求

```json
{
  "fen": "r1bqkb1r/pppp1ppp/2n2n2/4p3/2B1P3/5N2/PPPP1PPP/RNBQK2R w KQkq - 4 4",
  "depth": 14,
  "maxThinkingTime": 400,
  "variants": 3
}
```

| 字段 | 类型 | 必填 | 默认 | 范围 | 说明 |
|---|---|---|---|---|---|
| `fen` | string | ✅ | — | 6 段 FEN | 待分析局面 |
| `depth` | int | | 12 | 1 ~ 30 | 搜索深度上限 |
| `maxThinkingTime` | int(ms) | | 50 | 50 ~ 5000 | 思考时间上限 |
| `variants` | int | | 1 | 1 ~ 5 | MultiPV 条数，**REST 生效** |
| `searchmoves` | string | | "" | UCI 空格分隔 | 限定候选着法（自建增强，真正生效） |
| `taskId` | string | | "" | ≤64 | 原样回显 |

`depth` 与 `maxThinkingTime` **先到先停**。小程序建议：`depth 12~16` + `maxThinkingTime 300~600`，
实测中局单请求端到端 0.3~1.0s。

## 4. `POST /v1` 成功响应（200）

> 下面是**结构示例**，数值会随局面/深度变化，**不要拿这些数字写断言**。
> 可断言的实测数据在 §5.1。

```json
{
  "type": "bestmove",
  "fen": "r1bqkb1r/pppp1ppp/2n2n2/4p3/2B1P3/5N2/PPPP1PPP/RNBQK2R w KQkq - 4 4",
  "turn": "w",
  "move": "d2d3", "san": "d3", "lan": "d2d3",
  "from": "d2", "to": "d3", "piece": "p",
  "captured": null, "promotion": null, "flags": "n",
  "eval": 0.22, "centipawns": "22", "mate": null, "winChance": 52.2,
  "depth": 14, "seldepth": 17, "nodes": 61629,
  "continuationArr": ["d2d3","f8c5","c2c3"],
  "engine": { "name": "Stockfish", "version": "Stockfish 16", "source": "self-hosted" },
  "elapsedMs": 312, "timedOut": false, "terminal": false, "taskId": "",

  "lines": [
    { "rank": 1, "multipv": 1, "uci": "d2d3", "san": "d3", "from": "d2", "to": "d3",
      "scoreCp": 22, "scoreMate": null,
      "pv": ["d2d3","f8c5","c2c3"], "pvSan": ["d3","Bc5","c3"],
      "depth": 14, "seldepth": 17, "nodes": 61629, "debug": "info depth 14 …" },
    { "rank": 2, "multipv": 2, "uci": "f3g5", "san": "Ng5", … },
    { "rank": 3, "multipv": 3, "uci": "e1g1", "san": "O-O", … }
  ]
}
```

### 4.1 类型坑（实测确认，写死别猜）

| 字段 | 实测类型 | 备注 |
|---|---|---|
| `centipawns` | **string** | `"22"`、`"10000"` |
| `mate` | **string \| null** | `"1"` = 白方一步杀；`"-1"` = 黑方一步杀 |
| `lines[].scoreCp` | **number \| null** | 已是行棋方视角 |
| `lines[].scoreMate` | **number \| null** | 已是行棋方视角，`1` = 行棋方一步杀 |
| `eval` | number | 白方视角，单位 pawn |

### 4.2 `lines` 数组的缺口

`lines[]` **没有 `captured` 和 `promotion`**（实测字段只有
`rank, multipv, uci, san, from, to, scoreCp, scoreMate, pv, pvSan, depth, seldepth, nodes, debug`）。
端上契约的 `line.captured` 只能从**顶层 `captured`** 取（它对应第 1 线），其余线置 `null`。
界面若要用「是否吃子」图标，建议只用第 1 线的，或本地用 chess.js 重放一次 UCI 补齐。

## 5. 字段映射：服务端 → 端上 `engine.js` 契约（**核心**）

端上契约（AGENTS.md §4，冻结）：

```js
{ engine, fen, depth, nodes, elapsedMs, sideToMove,
  lines: [{ rank, uci, san, from, to, captured, scoreCp, scoreMate, pv, pvSan }],
  terminal }
```

| 端上字段 | 服务端来源 | 换算 |
|---|---|---|
| `engine` | 固定 `'stockfish'` | 与本地 `'mini-ab'` 区分 |
| `fen` | `fen` | 直取 |
| `depth` | `depth` | 直取 |
| `nodes` | `nodes` | 直取 |
| `elapsedMs` | 客户端计时 | 服务端 `elapsedMs` 是引擎耗时，不含网络 |
| `sideToMove` | `turn` | 直取 |
| `lines[].rank` | `lines[].rank` | 1..N |
| `lines[].uci` | `lines[].uci` | 直取 |
| `lines[].san` | `lines[].san` | 直取 |
| `lines[].from` / `to` | `lines[].from` / `to` | 直取 |
| `lines[].captured` | **顶层 `captured`**（仅第 1 线） | 其余线 `null` |
| `lines[].scoreCp` | **`lines[].scoreCp`** | **直取，不要换算** |
| `lines[].scoreMate` | **`lines[].scoreMate`** | **直取，不要换算** |
| `lines[].pv` | `lines[].pv` | 直取（UCI 数组） |
| `lines[].pvSan` | **`lines[].pvSan`** | **直取**，服务端已给，不必本地转换 |
| `terminal` | 本地算（`game.js#status`） | 服务端终局会 400，正常响应里恒 `false` |
| `source`（新增） | 固定 `'remote'` | 只加字段，不改既有字段 |

> 相比 `远端引擎接入方案-chess-api.md` §2.2，有两处可以省：
> **`pvSan` 不用本地转换**（服务端直接给）、**分数不用客户端换算**（`lines[]` 已是行棋方视角）。
> 换算逻辑只在连 chess-api.com 兜底时才需要（它没有 `lines[]`）。

### 5.1 视角换算（只在兜底到 chess-api.com 时用）

```
顶层 eval / centipawns / mate  = 白方视角
lines[].scoreCp / scoreMate    = 行棋方视角
行棋方视角 = 白方视角 × (turn === 'w' ? 1 : -1)
```

实测（`rnb1kbnr/pppppppp/8/8/8/8/PPPPPPPP/RNBQKBNR b KQkq - 0 1`，黑方缺后、轮黑走）：

```
turn = "b" | eval = 7.29 | centipawns = "729"        ← 白方视角：白大优
lines[].scoreCp = [-729, -739, -742]                 ← 行棋方视角：黑大劣
```

杀棋（`6k1/5ppp/8/8/8/8/5PPP/R5K1 w - - 0 1`）：

```
move = "a1a8" | san = "Ra8#" | mate = "1" | centipawns = "10000"
lines[0].scoreMate = 1 | winChance = 100
```

## 6. 错误与回落策略

统一结构（`type: "error"`）：

```json
{"type":"error","error":"GAME_OVER","text":"Game over: checkmate",
 "details":{"fen":"…","reason":"checkmate","turn":"w"}}
```

| error code | HTTP | 客户端动作 |
|---|---|---|
| `INVALID_FEN` / `ILLEGAL_POSITION` / `INVALID_INPUT` / `PARAM_OUT_OF_RANGE` | 400 | **不重试、不回落**，修请求（属本地 bug） |
| `GAME_OVER` | 400 | 显示终局；**本地前置判终局**，别浪费这次往返 |
| `RATE_LIMITED` | 429 | 退避后重试一次，仍失败 → **回落本地** |
| `QUEUE_FULL` / `ENGINE_UNAVAILABLE` | 503 | **回落本地** |
| `ANALYZE_TIMEOUT` | 504 | **回落本地** |
| `BUSY` | 409 | 仅 WS 场景（同一连接内重发） |
| 网络失败 / 超时 | — | **回落本地** |

**回落必须显形**（方案 D15）：结果带 `source: 'remote' | 'local'`，界面标注实际来源，
不允许静默切换。限流默认 60 次/分钟（burst 20），联调够用，但自动分析要 debounce。

## 7. 与 chess-api.com 的差异（切换上游时要知道）

| 行为 | chess-api.com | 自建服务 |
|---|---|---|
| REST MultiPV | ❌ `variants` 被忽略 | ✅ REST 直接返回 `lines[]` |
| `searchmoves` | ❌ 忽略 | ✅ 生效 |
| `lines[]` | 无 | ✅ 有，含 `pvSan` |
| 显式 `multipv` 字段 | 无（要从 `debug` 正则解析） | ✅ 有 |
| `taskId` | 不回显 | ✅ 回显 |
| 终局校验 | ❌ 不校验（会返回非法着） | ✅ 返回 `GAME_OVER` 400 |
| 错误 HTTP 码 | 恒 200 + body 报错 | 真实状态码 + 同结构 body |
| 参数上限 | depth≤18、思考≤100ms | depth≤30、思考≤5000ms、variants≤5 |

判错统一看 `body.type === 'error'` → **同一份客户端代码两个上游都能连**。

## 8. WebSocket（可选）

`wss://<host>/v1`，请求体与 §3 相同。消息序列（实测）：

```
log → log → info → ready → move ×N → bestmove → done
```

- `ready` 是自建增强（明确可发请求）；`move` 每条带显式 `multipv` 字段。
- **同一连接内串行**：上一个 `done` 之前再发会收到 `BUSY` 409。
- 空闲 120s 自动关闭；全局连接上限 200。

**什么时候才用 WS**：只在你想要「深度渐进显示」时。除此之外用 REST——
小程序 `wx.connectSocket` 全局同时最多 1 个，且预览环境大概率缺失（AGENTS.md §8 的探测降级原则）。

---

## 9. 小程序平台约束

- **合法域名**：`request`（用 REST）或 `socket`（用 WS）名单都要加域名，HTTPS/WSS；**大陆主体需 ICP 备案**。
- **超时**：`wx.request` 建议 `timeout: 10000`（正常 <1.5s）。
- **隐私**：只发 FEN，不含个人信息；`request`/`socket` 不在《隐私接口》清单，不新增声明。
- **预览环境**：先 `device.canRequest()` 探测，缺失即回落本地，绝不靠报错兜底。
- **GPL**：仅 HTTP 调用、不分发二进制 → 不触发开源义务。**任何 Stockfish 二进制/wasm 都不得进小程序包**。

## 10. 接入代码骨架

新建 `utils/remote-engine.js`，与 `utils/engine.js` 的 `analyze()` **同构**（只多 `source` 字段）：

```js
const BASE = 'https://ai-chess-server.app.workbuddy.host' // 联调；正式版换已备案域名
const TIMEOUT_MS = 10000

// 回落本地：需要时由 ai-client 注入，避免循环依赖
let fallback = null
function setFallback(fn) { fallback = fn }

function clamp(v, min, max, dflt) {
  const n = Number(v)
  return isFinite(n) ? Math.min(max, Math.max(min, Math.round(n))) : dflt
}

function request(options) {
  return new Promise((resolve, reject) => {
    wx.request(Object.assign({}, options, {
      timeout: TIMEOUT_MS,
      success: (res) => resolve(res),
      fail: (err) => reject(err),
    }))
  })
}

/** 服务端响应 → 端上 engine.js 契约 */
function normalize(body, multiPV, startedAt) {
  const raw = Array.isArray(body.lines) && body.lines.length ? body.lines : [body]
  const sign = body.turn === 'w' ? 1 : -1

  const lines = raw.slice(0, multiPV).map((l, i) => ({
    rank: l.rank || i + 1,
    uci: l.uci || l.move,
    san: l.san,
    from: l.from,
    to: l.to,
    captured: i === 0 ? (body.captured || null) : null,
    // 优先用 lines[]（服务端已换成行棋方视角）；没有 lines[] 时才自己换算
    scoreCp: l.scoreCp != null
      ? l.scoreCp
      : (body.centipawns != null ? Number(body.centipawns) * sign : null),
    scoreMate: l.scoreMate != null
      ? l.scoreMate
      : (body.mate != null ? Number(body.mate) * sign : null),
    pv: l.pv || l.continuationArr || [],
    pvSan: l.pvSan || [],
  }))

  return {
    engine: 'stockfish',
    fen: body.fen,
    depth: body.depth || 0,
    nodes: body.nodes || 0,
    elapsedMs: Date.now() - startedAt,
    sideToMove: body.turn,
    lines,
    terminal: null,
    source: 'remote',
    timedOut: !!body.timedOut,
  }
}

async function analyze(input) {
  const opts = input || {}
  const multiPV = clamp(opts.multiPV, 1, 5, 3)
  const startedAt = Date.now()

  try {
    const res = await request({
      url: BASE + '/v1',
      method: 'POST',
      header: { 'content-type': 'application/json' },
      data: {
        fen: opts.fen,
        depth: clamp(opts.depth, 1, 30, 14),
        maxThinkingTime: clamp(opts.maxTimeMs, 50, 5000, 400),
        variants: multiPV,
      },
    })

    const body = res.data
    // 判错一律看 body.type —— 同时兼容自建服务与 chess-api.com
    if (!body || body.type === 'error') {
      throw Object.assign(new Error((body && body.text) || 'remote error'), {
        code: (body && body.error) || 'BAD_RESPONSE',
        statusCode: res.statusCode,
      })
    }
    return normalize(body, multiPV, startedAt)
  } catch (err) {
    // 请求类错误（400）不回落，是本地 bug；其余回落本地并标注来源
    const code = err.code || ''
    const isBadRequest = err.statusCode === 400 ||
      ['INVALID_FEN', 'ILLEGAL_POSITION', 'INVALID_INPUT', 'PARAM_OUT_OF_RANGE', 'GAME_OVER'].includes(code)
    if (isBadRequest || !fallback) throw err

    const local = await fallback(opts)
    local.source = 'local'
    local.degradedFrom = code || 'network'
    return local
  }
}

module.exports = { analyze, setFallback }
```

`ai-client.js#analyzePosition` 按 `engine` 开关分流即可，**`analyze()` 输出契约不变**。

## 12. 给 AI 助手的硬性提醒

- **不要改 `utils/engine.js` 的 `analyze()` 输出契约**（AGENTS.md §4 冻结），远端靠同构适配。
- **不要把顶层 `eval`/`centipawns`/`mate` 当行棋方视角** —— 那是白方视角，用 `lines[]`。
- **不要静默回落** —— 必须带 `source` 并让界面显形（方案 D15）。
- **不要把 `app.workbuddy.host` 写进正式版配置** —— 它是联调域名，正式版走已备案域名。
- **不要为了让远端跑通而弱化本地引擎** —— 本地是「四条保底通道」之一，离线必须可用。
- **不要引入任何 Stockfish 二进制/wasm 到小程序包**。
- 改完跑三套既有测试，全绿再交付。
